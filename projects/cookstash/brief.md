# Product Brief: Cookstash

---

## Executive Summary

**Cookstash** is an app that lets people save the cooking videos they discover on social media, organize them into a personal recipe library, and plan their cooking directly from that library. It closes the gap between "I saw a recipe I liked" and "I actually cooked it" — turning scattered social-media inspiration into a structured, repeatable cooking routine.

---

## Core Vision

### Context

Cooking inspiration today comes almost entirely from social video — Reels, YouTube Shorts, TikTok — but that inspiration has nowhere to live. Cooktash gives users a personal library to store the cooking videos they've found, and a planning layer on top of it, so saving a video is the start of a cooking plan rather than a dead end.

### Target Users

**Who:** People aged 20–45, living busy lives.

**What they want:** To use apps that make daily life more productive — including a daily task like cooking. They're not looking for a cooking encyclopedia; they're looking to reduce the mental and manual overhead of getting a meal on the table.

### User Goal

Improve their productivity in **planning** and **cooking** meals.

To reach that goal, users need to be able to:
- **Plan efficiently** — quick and effective
- **Cook efficiently** — quick and yummy

---

## Problems

### What prevents users from planning efficiently?

| Scenario | The question they're stuck on | The cost |
|---|---|---|
| A single meal | "What's to cook for dinner?" | Doesn't know what to cook |
| Monday planning | "What's to cook for breakfast, lunch, and dinner?" | Takes a long time to build a menu for every meal in the day |
| An event (e.g. Christmas dinner) | "What's to cook for this dinner?" | Takes a long time to build a menu for a whole event |

### What prevents users from cooking efficiently?

| Scenario | The friction | The cost |
|---|---|---|
| Recalling a recipe | "I saw a tutorial video on YouTube Shorts before — I need to find it again to rewatch." | Time lost re-searching for the instructional video |
| Building a shopping list | "Which ingredients do I already have, and which do I need to buy for this dish?" | Time lost manually listing ingredients for grocery shopping |
| Getting help shopping | "This shopping list is long — I need to ask friends to help buy some of it." | Time lost re-listing what to ask friends to pick up |

---

## Interventions — How Cooktash Reduces the Friction

| Intervention | Problem it addresses |
|---|---|
| Allow users to save recipe videos directly from social media channels | Recipes are scattered and hard to re-find |
| Library as a collection of cooking recipes | No single home for saved inspiration |
| Create categories and group recipes by user interest | Hard to browse a growing library |
| Suggestion of dishes to cook | "I don't know what to cook" indecision |
| Calendar format as a planning framework — quick input for a day/week/month | Slow to build a menu for daily/weekly meals |
| Event menu format as a framework — quick input across dessert, main course, drink, decoration, etc. | Slow to build a menu for a one-off event |
| Video as the recipe itself in the library — search and watch instantly | Time lost hunting for the original video |
| Auto-generate a grocery shopping list from the plan | Time lost manually listing ingredients to buy |
| Simply share a grocery shopping list with a friend | Time lost re-listing what to ask friends to help shop |

---

## Proposed Feature Pillars

Grouping the interventions above into buildable product surfaces:

1. **Save** — Save cooking videos from social channels straight into a personal library.
2. **Library** — Browse, categorize, and group saved recipes by interest; the video itself is the recipe, watchable on demand.
3. **Plan** — Two planning modes: a **calendar** framework for everyday day/week/month meals, and an **event menu** framework for occasions (dessert, main, drink, decoration, etc.).
4. **Shop** — Auto-generate a grocery list from the plan, and share it with a friend in one step.

This is the same **Save → Organize → Plan → Shop → Share** loop that anchors the Cooktash product story.

---

## Success Signals

*How we'd know Cooktash is closing the gap it targets:*

| Behavior | Signal it validates |
|---|---|
| User saves a video directly into the library | Save friction is low enough to build a habit |
| User builds a plan (day, week, or event) from library items | Planning is faster than starting from a blank page |
| Grocery list is generated from a plan rather than typed manually | The plan → shop handoff is actually automated |
| Grocery list is shared with another person | Sharing removes the need to re-type a list for someone else |
| User returns to plan again after their first plan | The tool has replaced the old workaround (memory, notes, re-searching) |

## Visual & Experience Direction

Cookstash should feel:

- Modern
- Minimal
- Clean
- Approachable
- Effortless

### Visual principles

- **Strong hierarchy** — Make the primary task and most important information immediately recognizable.
- **Purposeful whitespace** — Use space to separate concepts and reduce cognitive load without making information unnecessarily sparse.
- **Restrained visual language** — Avoid unnecessary decoration, excessive borders, shadows, gradients, or competing visual treatments.
- **Clear typography** — Use typography to establish hierarchy and make recipe information easy to scan.
- **Content-first** — Cooking videos, recipes, meal plans, and grocery items should remain the visual focus.
- **Simple interaction surfaces** — Prefer straightforward, familiar controls over visually complex interactions.
- **Consistent design system** — Reuse established components, tokens, spacing, and interaction patterns.
- **High signal-to-noise ratio** — Every prominent element should support the user's goal, decision, or next action.

### Experience principles

- Make saving a recipe feel effortless.
- Make browsing feel lightweight and visual.
- Make planning feel faster than starting from a blank page.
- Keep the user's cooking context visible when it helps them make decisions.
- Reveal complexity progressively rather than presenting everything at once.
- Prioritize the user's next meaningful action over secondary functionality.
